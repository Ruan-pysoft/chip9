The chip9 has a few devices which the CPU can send instructions to via the 0XXX family of instructions.
The device gets read/write access to the 16-bit register specified by the second nibble of the instruction,
and a command nibble specified by the third nibble of the instruction to select which action to take.

Graphics chip:
  Preliminary screen resolution: 768x512

  The graphics chip starts in mode 0.
  The screen starts switched on.

  The graphics chip has a screen with a logical resolution of 384x256
  The native colour format is 16-bit rgba,
  with the red, green, and blue channels each using five consecutive bits in that order
  and alpha using a single bit (transparent/opaque), the least significant bit.

  Graphics modes:
    Pixel mode (mode 0): memory use is [$8000,$9800)
      read 96x64 (=6144) pixels of data from memory address $8000, and display them in 4x4 pixel groups
    Sprite mode (mode 1): [$8000,$A0C0]
      Read 32 sprites from memory address $8000,
      where each 16x16 sprite consists of 256 consecutive words indicating its colour.
      The first 16 sprites are the foreground sprites and the last 16 are the background sprites.

      Read the foreground index set (24x16=384 nibbles) from address $A000
      and the background index set (24x16=384 nibbles) from address $A060.

      The background sprites are drawn first, then the foreground sprites over them
      (with transparent foreground pixels not drawn)
    Indexed pixel mode (mode 2): memory use is [$8000,$9810)
      read 192x128 packed nibbles of colour indices from memory address $8000 (6144 words).

      read 16 colour values from memory address $9800 as the index table.

      The screen is painted with these pixels.
    Indexed sprite mode (mode 3): [$8000,$9730)
      The 4096 words at memory address $8000 contain 4 sprite sets,
      where each sprite set consists of 16 consecutive sprites,
      and each sprite consists of 256 packed nibbles, each a colour index. (1024 words per sprite set)
      These are the sprite sets, respectively, for layers 1, 2, 3, and 4.

      A screen consists of 1536 consecutive sprite indexes, each consisting of a single nibble. (384 words)
      The first 24x16=384 nibbles belongs to layer 1, the next 24x16=384 to layer 2, then layer 3, then layer 4.
      The 1536 words at memory address $9000 contains screen 1 through screen 4.

      Starting at memory address $9600 then read 256 words,
      where each 16 words is a colour index table.
      First the 4 index tables for layer 1 through layer 4 of screen 1,
      then the 4 index tables for layer 1 through layer 4 of screen 2,
      then screen 3 then screen 4.

      Starting at memory address $9700 then read 48 words,
      consisting of 24x16=384 bit-pairs,
      each bit pair a screen index.

      Then, at each 16x16 sprite position on the display:
       - the active screen is slected by the current screen index
       - the sprites of layers 1 through 4 of the current screen is drawn
         - layer 4 far back, layer 1 most front
         - only layer 4 has its transparent pixels drawn

  Commands (specified by the command nibble):
    0 :: read current graphics mode into Vr
    1 :: set graphics mode from Vr; behaviour on invalid graphics mode is undefined
    2 :: read screen state into Vr (on=all bits set, off=no bit set)
    3 :: set screen state from Vr (on=any bit set, off=no bit set)

Clock chip:
  The Chip9 runs at a clock speed of 3 MHz,
  split into 60 frames a second with 50,000 clock cycles per frame.

  During the last 512 frames of each cycle
  the graphics chip will draw do the screen, one row at a time.
  The cpu will not tick during this time.
  Implementations could write the whole screen at once
  and then sleep until the 512 cycles expired.

  The clock keeps track of:
   - cycle: the current cycle in the frame
   - frame: the current frame in the second
   - second: the number of seconds since boot
   - epoch: the amount of times the no. of seconds since boot has overflowed to zero
   - timer: a counter that ticks down every cycle until it hits zero
   - frame timer: a counter that ticks down every frame until it hits zero

  Commands (specified by the command nibble):
    0 :: read cycle into Vr
    1 :: read frame into Vr
    2 :: read second into Vr
    3 :: read epoch into Vr

    8 :: read timer into Vr
    9 :: set timer to Vr
    A :: read frame timer into Vr
    B :: set frame timer to Vr
    C :: suspend cpu for Vr cycles (including graphics-drawing cycles)
    D :: suspend cpu until the end of the current frame (cpu only ticks again at the first cycle of the next frame)
